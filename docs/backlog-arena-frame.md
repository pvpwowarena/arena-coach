# Backlog — килл-таргет с номером арена-фрейма («арена 1, маг»)

> Статус: **отложено до Phase 5 (CV/OCR)**. Решение 2026-07-26 (Влад).
> Причина — нет рабочего realtime-канала доставки ростера arena1/2/3 в бой.

## Что просили (фидбэк 2026-07-24/26)

Килл-таргет должен называть **номер вражеского фрейма** — «Килл-таргет: арена 1 (Маг)»,
чтобы игрок сразу таргетил `/target arena1` / кликал нужный фрейм. Особенно ценно, когда
у врагов **дубли классов** (маг+маг): «убей мага» неоднозначно, а «арена 1» — точно.

## Почему сейчас нельзя (технический блокер)

Позицию `arena1/2/3` знает **только клиент** (аддон): `UnitGUID("arena1")` в `ScanEnemies`
(`addon/ArenaCoach/Tracker.lua`) уже собирает slot→class→name. Но **доставить** эту карту
мосту в бою нечем:

| Канал аддон→мост | Realtime? | Итог |
|---|---|---|
| chat-лог (`SendChatMessage` → whisper-to-self) | ❌ | На Anniversary буфер (~48КБ) **не флашится до выхода из игры**; `LoggingChat(false→true)` — no-op (живой тест 2026-07-23). Именно поэтому Phase 4.2 ушла на combat-лог. |
| combat-лог | ❌ (для произвольных данных) | Мост читает его в realtime, но аддон **не может писать** в него произвольные строки — только через каст (запрещено: no input injection, ToS). |
| SavedVariables | ❌ | Флашится лишь на `/reload` и logout (ADR-0003). |

Combat-лог — единственный realtime-источник моста — **позиции фрейма не содержит** (только
GUID/имя/флаги; arena-slot там нет).

Вывод: без нового канала доставки фичу realtime не сделать. Class-level килл-таргет
(«убей друида») работает уже сейчас и для уникальных классов однозначен.

## Путь решения — Phase 5 (CV/OCR)

Надёжный realtime-источник позиции фрейма — **чтение экрана**:

1. Захват региона вражеских unit-фреймов (`mss`), template-matching иконок классов
   (или OCR имён) по фиксированным позициям arena1/2/3 → карта `slot → class/name`.
2. Мини-компаньон/расширение моста публикует карту в backend (тот же `/v1/events` или
   отдельный `/v1/roster`), либо мост сам её потребляет.
3. Backend: `EnemyInfo.arena_slot` (аддитивно, как `spec`); killtarget-строка показывает
   «арена N (класс)», когда slot известен, иначе — текущий class-based (без регресса).

## Что уже готово под эту фичу (Phase 4.7)

- **Частичный матч** (`retriever.find_partial_candidates`) и **распознавание класса/спека
  по гейт-бафам** — прямой задел под «стелс-предугадывание» (держать варианты врагов и
  выбирать по бафам). См. backlog #7.
- Плагин-точка: добавить `arena_slot` в `EnemyInfo` и в форматирование килл-таргета —
  изменения локальные и обратно совместимые.

## Дешёвая альтернатива-проверка (если дойдут руки раньше Phase 5)

Если на будущей сборке клиента chat-лог **вдруг** начнёт флашиться в бою — addon-roster
станет жизнеспособным (дешевле OCR). Проверяется мини-тестом: `/ac roster` эмитит
`[AC#ARENA_ROSTER#arena1:CLASS:Name#...]` + форс-флаш; смотрим, видит ли мост строку
во время матча (а не после выхода). Пока исходить из того, что канал мёртв.
