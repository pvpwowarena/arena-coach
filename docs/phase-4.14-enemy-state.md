## 1. Что было не так

Вся боевая речь шла из `reactions.py` — таблицы «способность → фраза». Таблица не
знает ничего о ситуации, поэтому её реплики в лучшем случае пересказывают видимое:

| Говорил бот | Что игрок уже знал |
|---|---|
| «Овца — ломай уроном, если это хилер» | он видит овцу |
| «Тринкет ушёл — вешай контроль и дожимай» | он видит анимацию тринкета |
| «Против рога и рога. Килл таргет — рога» | …которая из двух? |

При этом данные для гораздо более ценных подсказок **уже доезжали** до бэкенда: мост
форвардит каждый каст врага вместе с ником источника (Phase 4.12). Не хватало только
памяти между событиями.

## 2. Что сделано

### 2.1. Реестр состояния врага — `orchestrator/enemy_state.py`

`EnemyTracker` держит по игроку состояние текущего матча:

* **кулдауны**: враг применил способность → знаем, когда она вернётся, и знаем, что
  до тех пор её НЕТ;
* **карту «ник → класс»**: ростер в `ARENA_START` несёт только классы (в
  `EnemyInfo` имён нет вовсе), но каждый каст несёт и ник, и — через каталог
  спеллов — класс кастера. Бэкенд строит карту сам, без релиза моста;
* **производные состояния** рёберными детекторами: `poll_open_window`
  («у него ни тринкета, ни дефа») и `poll_ready_again` («КД вернулся»). Оба меняются
  БЕЗ нового события, поэтому объявляются один раз на переход.

Записи в реестр идут **до** хинт-фильтров и троттлинга: подавленная реплика не должна
стирать знание, иначе бот «забудет», что тринкет уже потрачен.

### 2.2. Кулдауны — только из sourced-слоя

`kb/glossary/realtime_spells.json` получил поле `cooldown_s`. Значения **перенесены
скриптом** `tools/derive_cooldowns.py` из `kb/glossary/abilities.json` (поле `cd`:
«60с», «5 мин») — 22 из 88 записей. Остальные 66 остаются без поля, и про них бот
говорит только «потрачено», без обратного отсчёта. Это тот же принцип, что
`GLOSSARY_GAPS` в `reactions`: механику 2.4.3 не экстраполируем.

```
python tools/derive_cooldowns.py          # отчёт
python tools/derive_cooldowns.py --write  # записать
```

**Кулдаун PvP-тринкета в sourced-слое не подтверждён.** Поэтому «тринкета нет»
держится до конца матча и «тринкет вернулся» не объявляется вовсе. Появится источник
— впиши `cooldown_s` для тринкета, и обратный отсчёт заработает без правок кода.

### 2.3. Новые подсказки — `orchestrator/state_advice.py`

| Событие | Голос | Почему это «вау» |
|---|---|---|
| Тринкет + деф потрачены | «У Shadow ни тринкета, ни дефа — дожимайте.» | учёт, который игрок в бою не ведёт |
| Тяжёлый КД вернулся (≥60с) | «У Cekraj снова есть ваниш.» | окно закрылось, и на экране это не видно |
| Тринкет при дубле класса | «Тринкета нет у Shadow — всё на него.» | «тринкет ушёл» не говорило, у кого |

Возврат КД короче 60 секунд не объявляется: кик откатывается каждые 24с, и озвучивать
это значило бы вернуть ту самую «заевшую пластинку».

Подсказки по состоянию идут **перед** реакцией на событие: бюджет речи один на двоих,
и если реакцию после этого съест интервал — так и надо, игрок услышал более важное.
Статус такого события — `sent`, а не `throttled`.

### 2.4. Дубли классов

Три места, и все три нужны, потому что информация появляется постепенно:

1. **Анонс на воротах** — «рога и рога» схлопнулось в **«дабл рога»**: так этот состав
   называют сами игроки, и это сразу задаёт режим боя (было — звучало как сбой
   синтезатора и ничего не сообщало).
2. **Первый тринкет** — самый ранний момент, когда дубль вообще разрешим: до него оба
   одинаковых врага равнозначны. Голос называет ник, DM добавляет строку
   «теперь цель однозначна: бей **Shadow**».
3. **Повторный `ARENA_START`** — разрешение дубля вошло в сигнатуру дедупа
   (`kb:{slug}|{dup_voice}`), иначе дедуп по одному слагу гасил бы уточнение цели.

Когда никто ещё не тринкетнул, бот называет не ник, а **критерий**: «Две рога — бей ту,
что без тринкета». Ник без причины игрок не запомнит, а критерий работает весь бой.

Ник в голосе появляется **только** при дубле. В остальных случаях он лишь удлиняет
фразу (а поллер моста синтезирует речь блокирующе — каждое слово это задержка
следующей подсказки). Таблица `reactions` остаётся безымянной — её тест это проверяет.

### 2.5. Латиница в голосе — `kb/translit.py`

Ник в русской фразе RU-синтезатор читает кашей. Перед отправкой в TTS (и только там —
в DM текст остаётся человеческим) вся латиница транслитерируется в кириллицу:
`Cekraj` → «Кекрадж». Побочно это чинит и старую жалобу «кривоватый перевод»:
`slang` для 46 слагов из 63 отдаёт `en_name`, то есть английское имя способности
внутри русской фразы.

## 3. Как это звучит (симуляция 2v2 vs дабл-рога на реальной KB)

```
0:00  Арена. Против дабл рога. Килл таргет — рога.
0:03  Сап — опенер пошёл, не разбредайтесь.
0:08  Шадов: Чип — стан-цепь пошла, тринкет держи.      ← ник: рог двое
0:12  Тринкета нет у Шадов — всё на него.               ← цель стала однозначной
0:20  У Шадов ни тринкета, ни дефа — дожимайте.         ← НОВОЕ: невидимое состояние
0:30  Кекрадж: Ваниш — жди реопен, встаньте вместе.
0:45  Кекрадж: Блайнд — тринкеть только если добивают.
1:48  У Кекрадж снова есть блайнд.                      ← НОВОЕ: окно закрылось
```

Из восьми реплик три сообщают то, чего на экране нет. До 4.14 таких было ноль.
