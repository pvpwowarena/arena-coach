## 1. Что убрано и почему

### 1.1. Discord-voice (Phase 4.5) — удалён целиком

Он был вытеснен Phase 4.6 (локальный голос: мост забирает ту же фразу через
`GET /v1/hints` и читает системным TTS у игрока) и всё время стоял **выключенным по
умолчанию** — `DISCORD_VOICE_CHANNEL_ID=0`. То есть в проде он не работал ни дня, но
тянул за собой инфраструктуру:

| Удалено | Что это было |
|---|---|
| `backend/arena_coach/bot/voice.py` (334 строки) | `VoiceManager`, `EdgeTTSEngine`, HTTP-приёмник |
| `pipeline._send_voice_hint` | хоп api→bot по `http://127.0.0.1:8100/speak` |
| `Settings.discord_voice_channel_id`, `voice_http_host/port`, `voice_tts_voice` | конфиг |
| `edge-tts`, `PyNaCl` в `backend/pyproject.toml` | зависимости |
| установка `ffmpeg` в `ops/scripts/vps-deploy.sh` | системная зависимость деплоя |
| `tests/test_voice.py` (30 тестов) | тесты снятой подсистемы |

`/coach voice on|off|only` **остался** и теперь управляет локальным голосом — эта
настройка всегда читалась пайплайном перед постановкой фразы в очередь.

Побочный эффект в пользу локального голоса: раньше `voice_mode="only"` подавлял текст
только если Discord-voice подтвердил проигрывание. Теперь «only» опирается на факт
постановки в очередь. Это осознанный сдвиг: игрок сам выбрал «только голос», и если его
мост не запущен, это его настройка, а не наша догадка.

### 1.2. Боевой DM — по умолчанию не шлём

Живой тест 30.07: «огромный текст в бою читать не очень удобно». Тогда боевой DM урезали
до двух строк — но игрок его в бою всё равно не читает, а каждый такой DM это вызов
Discord API при потолке 12 реплик в минуту.

Теперь `player_settings.combat_text` (миграция **0005**, default `off`):

| Что | По умолчанию |
|---|---|
| Разбор на воротах (`ARENA_START`) | **всегда** — его читают |
| Постматч-разбор | **всегда** — его читают |
| Боевые реплики (тринкет, КД, состояние врага) | голос да, текст **нет** |

Включить текст обратно — `/coach text on`.

**Предохранитель:** текст глушится только если игроку реально есть что услышать. Если
`/coach voice off` или фразы нет — боевой DM уходит как раньше, иначе игрок остался бы
вообще без подсказки. Это зафиксировано тестом `test_without_voice_text_survives`.

## 2. Что НЕ убрано (и почему)

- **Discord-бот как таковой.** `/matchup`, `/opener`, `/glossary` вне боя, постматч-отчёт,
  `/coach`, вайтлист, `/coach stats` — это готовый UI за нулевую работу. Своё писать дороже.
- **API.** Два реальных требования: ключ Anthropic (игрокам его отдавать нельзя — LLM-разбор
  незнакомых сетапов и постматч) и обновления KB.

## 3. Что дальше — разобрано, но не сделано

После 4.7 и 4.14 весь боевой путь детерминирован: KB — статические файлы, `reactions` /
`state_advice` / `enemy_state` — чистый Python без БД и Discord. Мост уже питоновский
бинарь. Значит `orchestrator/` (≈3300 строк) технически может исполняться локально, и
тогда исчезают: сетевая задержка, очередь `/v1/hints` с TTL (она существует ТОЛЬКО из-за
серверного хопа) и класс отказов «бэк лёг».

Решающий довод не в чистоте, а в **Phase C из аудита** (пиксель-полоска аддона → HP, мана,
номер арена-фрейма, 5 раз в секунду): по HTTPS это не имеет смысла в принципе. Локальный
пайплайн — предпосылка для порогов добива.

**Цена:** если KB и логика лежат у игрока, гейтить доступ технически нельзя — кто получил
бинарь, получил продукт. Для монетизации это важно, поэтому ценную часть (LLM-разборы,
обновления KB) в любом случае стоит оставить серверной.

Порядок из аудита не меняется: сначала A2/A3 (автомат фаз + машинный `plan:` в KB) и A4
(заглушить низкоценные реакции) — там ценность; local-first — перед Phase C.
